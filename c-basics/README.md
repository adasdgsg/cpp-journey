# c-basics — 计算器三代

三个文件是同一条练习线的三代版本，水平是往上走的：
`2222 - 副本.c`（函数指针数组，刚摸到门）→ `3333.c`（加菜单和循环，但循环条件写崩）→ `FileName.c`（函数封装 + switch，结构最清楚）。

> 原文件是 GBK 编码，入库时统一转成了 UTF-8，代码内容一字未改。

---

## 1. `2222 - 副本.c`（497 字节，2026-09-25 20:49）

**练什么**：函数 + 函数指针数组，写一个「输入两个数 + 运算编号，输出结果」的计算器。
核心一行是 `double(*AAA[4])(double, double) = {jia, jian, chen, chu};`——把四个函数装进数组，
`AAA[n - 1](A, B)` 按下标调用。这个写法已经摸到「表驱动」的门了。

**问题**：
- `chu()` 里写的是 `return a + b;`——除法函数做加法，结果错。
- `if (a != 0 && b != 0)` 判断错了对象：除法只需保证**除数 b** 不为 0，a 是不是 0 无关。
- else 分支只 `printf("0");` 没 `return`，double 函数缺返回值是未定义行为（VS 警告 C4715）。
- `n` 没做范围检查，输入 0 或 5 就越界访问数组。
- `scanf_s` 是 MSVC 专有函数，gcc 下编不过（见文末）。

## 2. `3333.c`（700 字节，2026-09-25 23:31）

**练什么**：在上一版基础上加 `switch` 菜单 + `for` 循环，想做成「选 1 进入连续计算，选 2 退出」。
四个运算函数和函数指针数组写法与上一版一致，`chu()` 里改回了 `a / b`。

**问题**（这版问题最多）：
- **死循环**：`for (i = 0; i = 11111; i++)` 中间是赋值不是比较。`i = 11111` 恒为真，
  每轮把 i 重置成 11111，循环永远出不去——应该写 `i == 11111` 或 `i < 11111`。
- 循环体里 `scanf_s(..., &i)` 又读入 i，把循环变量本身改掉，等于双重破坏。
- `if (i == 333) break;` 因 i 恒为 11111，永远不会触发，break 形同虚设。
- `case(1)` 结尾没有 `break`，会穿透到 `case(2)` 直接打印「结束」。
- `chu()` 的守卫条件同样错成 `a != 0 && b != 0`，应只判 b；printf 分支依然缺 return。

## 3. `FileName.c`（907 字节，2026-09-24 16:48）

**练什么**：最贴近「正经工程」的一版——每个运算单独封装成函数，主函数用 `switch` 分发，
还写了注释（`//1输入 //2引用 //3输出`）。输入格式是「数 运算符编号 数」，即 `scanf_s("%lf %d %lf", &a, &F, &b)`。

**问题**：
- `double chebg(...)` 里把乘积存进 `int fz` 再 return，小数部分被截断（乘法精度丢失，加法除法则没有）。
- `double main()` 应为 `int main()`。
- `case(4)` 缺 `break`（已是最后一条，暂时不出错，但习惯要补）。
- 除法没判除数 0，`b = 0` 会得到 `inf`。
- `chebg` 是「cheng」打错，`jia/jian/chebg/chu` 命名不统一。

## 三类共性问题

三代版本的问题可以归到三类，每类都能单独拿出来理解：

| 类别 | 例子 | 后果 |
|---|---|---|
| 循环条件写成赋值 | `for (i = 0; i = 11111; i++)` | 死循环 |
| 该 return 的分支没 return | `chu()` 的 else 只 printf | 返回垃圾值（UB） |
| 精度被窄类型吃掉 | `int fz = jj * ff;` 再 return double | 小数被截断 |

## 编译说明（重要）

这三个文件都用 `scanf_s`，它是 **Visual Studio 的专有函数**，Linux 的 gcc 不认识：

```
error: implicit declaration of function 'scanf_s'
```

在 Ubuntu 里练，把 `scanf_s` 换成 `scanf` 即可（`%lf` 之类格式串不变）。
标准 C 里也没有 `scanf_s`，它属于 C11 Annex K 的可选扩展，gcc 默认不实现。
